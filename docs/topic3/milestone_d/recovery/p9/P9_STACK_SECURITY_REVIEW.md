# P9 stack security review

Source inspection covers D1 scope resolution, `FrozenResearchSnapshot`, `verified_real_cells`, `automatic_real_query`, the D4 Decimal verifier, research API and Streamlit. D1 fixes issuer/filing/period scope. The research snapshot verifies READY generation, manifest, path containment, payload hash and canonical source membership before exposing candidates. D2's real-source adapter requires the committed registry raw SHA, complete byte hash, C parser/chunker reconstruction, parent identity, SEC filing identity, selected table coordinates, iXBRL period/unit and visible multiplier. D4 reauthenticates operands and uses Decimal; comparisons require the same filing/parent/table/row/fact/unit/multiplier. P8 added only exact `total assets` ↔ `us-gaap:Assets` and INSTANT periods. It did not relax accepted source checks.

The four P7 HIGH repairs were rechecked: (1) `members.source.filing_id` forgery is refused by `validate_frozen_parent_membership`; (2) FAILED generation returns HTTP 409 with no value and restores to READY in the disposable clone; (3) a fair-value qualifier returns `NEEDS_CLARIFICATION` and no number; (4) percentage-point change returns `UNSUPPORTED_OPERATION` and no number. `p9_tamper_results.json` records 12/12 clone mutations refused and a restored untampered control; `p9_http_tamper_results.json` records raw-byte mutation HTTP 409 and restart control. `p9_semantic_results.json` records the financial qualifier checks. Original source hash and READY state were checked after restoration.

The authenticated research app is a separate `app.research_api` ASGI application. It requires a bearer token, compares credentials using `hmac.compare_digest`, caps body size at 16,384 bytes and question length at 2,000 characters, and uses a one-slot request semaphore. Live checks returned 401 for missing/invalid credentials and 422 for an overlong question. No unexpected import into accepted `app.main` or legacy RAG path appeared in the target-to-P8 diff. The accepted B/C/D1 tracked scientific artifacts were byte-identical across that diff.

A further 60 MiB disposable clone supported three parallel pinned readers during lexical publication. Twelve total source-bound reads retained the old generation, zero mixed-generation claims occurred, the new generation became active only in the clone and the old generation remained READY (`p9_concurrency_results.json`). This is local single-host evidence, not distributed publication proof.

Trust boundary: the committed D3 registry and pinned research snapshot are upstream trust anchors. Runtime Pydantic validation alone does not authenticate SEC bytes. These tests do not certify the Git checkout or host against a malicious local administrator. Unknown paraphrases and unsupported financial qualifiers may need additional contracts; no broad semantic completeness claim follows. Full distributed Qdrant publication/rollback and production penetration testing were not performed.
