# SEC source and provenance audit

Trust anchor: the committed D3 registry names the complete raw SHA256, CIK, accession and SEC URL. `verified_real_cells` requires the isolated snapshot's dataset manifest/generation to match that registry, then checks the parent is a member of the pinned lexical generation and its canonical payload hash matches. It confines all referenced paths to the owned research root. It rehashes complete raw bytes, invokes C `verified_source` (which validates saved structured/chunks and reconstructs canonical parents), checks selected parent fields, reparses with the accepted parser for physical table coordinates, compares normalized text hash, then rehashes raw bytes again. An untrusted request provides only a selection key, never a source binding.

The P&G source URL, raw SHA256, parent payload hash, table ID, row/column, iXBRL context/unit and structural paths are in `P0_REAL_SEC_TABLE_RECOVERY.md` and `real_sec_probe_v1.json`. The fact's issuer identifier matches the verified CIK; context dates match the visible column header; `iso4217:USD` and scale 6 are read from the authenticated source. The selected table is `OK`, while the filing retains `PARTIAL_EXTRACTION` warning. An independent read of the [SEC HTML](https://www.sec.gov/Archives/edgar/data/80424/000008042426000256/pg-20260930.htm) displayed the earnings statement at lines 116–120, including the 2026/2025 columns and 23,276/22,386 in millions. A web browser landing at the exact structural location was NOT_TESTED; a valid SEC URL alone is not a demonstrated clickable-cell navigation.

The new adapter does not certify all financial content in the filing, does not verify a human interpretation of `us-gaap:Revenues` beyond the narrowly accepted `NET SALES` row rule, and does not cover six table families. Synthetic tests reject changed fact attributes, entity, header, unit, duplicate resource IDs and >4 MB source. Cryptographic authentication is anchored to the **committed D3 source registry**; it is not provided by Pydantic structural validation. Changes to that registry require review as trusted code/data changes.
