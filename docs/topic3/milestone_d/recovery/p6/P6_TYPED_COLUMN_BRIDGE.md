# Typed column evidence bridge

D1 continues to return `NEEDS_CLARIFICATION` for the P&G quarter because its frozen catalog lacks typed comparative-column metadata. P6 permits refinement only when D1 has uniquely fixed CIK, a single unamended filing, manifest and generation; `COLUMN_PERIOD_METADATA_INCOMPLETE` must be the remaining uncertainty. A contradictory issuer/filter, invalid period syntax, explicit fiscal conflict or missing filing is never promoted. The P6 response retains `metadata_scope_status=NEEDS_CLARIFICATION` while `refinement_status=VERIFIED` means **only the selected cells** have source-backed columns. It does not rewrite D1's `RESOLVED` meaning.

`ColumnRefinementV1` records dataset generation/manifest, CIK, eligible filing IDs, requested ends, 64-candidate budget, original BM25 rank, selected parent and `RealCellObservationV1` cells. Each observation carries accession/filing, raw SHA256, parent payload hash, table/row/column, header path, duration start/end/months, iXBRL context/fact/unit, visible million-unit header, Decimal value and multiplier, source URL/structural locator, footnotes and extraction warnings. The complete bytes are matched to the committed D3 registry and reconstructed through accepted C provenance before a cell becomes eligible. Source status is `VERIFIED_SOURCE_CELL`; corpus-wide completeness is not implied.

The P&G alias is derived from the already verified issuer name and accepted only when the pinned, hash-authenticated SEC filing explicitly uses the quoted abbreviation near the company's self-description. It changes only a runtime P6 catalog view; the frozen catalog file and accepted D1 code/data contract are not rewritten. Alias authentication at this stage is a raw-hash/self-description check; the full canonical C reconstruction occurs again before cell acceptance.
