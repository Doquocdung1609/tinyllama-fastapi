# P11 development questions and provisional qrels

`scripts/p11_construct_dev_labels.py` inspected canonical structured tables and parent chunks from the two acquired **development** issuers before any new retrieval ranking. It fixed 10 positive queries and four scope/refusal controls in `p11_query_registry.json`. The 10 proposed grade-2 qrels span **seven unique parent IDs**; duplicate questions intentionally probe paraphrase or comparative-period wording against the same source row. The fixed source locator, issuer, accession, raw SHA256, table ID, row index, reporting-period header, unit observations, rationale and extraction warning are recorded per query. `p11_qrels.json` SHA256 is `0dda952f589390a1a7a42cbfa42465e4279dcf9384092cb357a27477fc1375b3`.

These labels come from explicit source table/row inspection, not BM25 or Dense ranking. They are **provisional**: no independent human reviewer verified financial relevance or exhaustive alternatives. A row label alone is insufficient proof of the right unit, segment, fiscal interpretation or every eligible parent. CAT and MCD both have partial table extraction; some otherwise plausible rows lack typed reporting periods. Refusal controls have empty eligible-parent lists with status `NOT_A_NEGATIVE_QREL`; they are not silently scored as zero-relevance qrels.

The program first failed closed on the CAT diluted EPS label because a terminal-rendered replacement character differed from the actual source en dash. The fixed spec uses the canonical U+2013 row label and revalidated exact row identity; no ranking was seen before this correction. The review packet retains the raw row/header context for human adjudication.
