## Change discipline

After owner approval, use one narrowly scoped Draft PR per approved stage; do not create those branches now. Require C regression and meaningful new contract tests before integration. Proposed interface can be opt-in/versioned; no silent switch of Financial Search defaults or legacy Chat/RAG. Source hashes, parser/chunker identities, prefix/model assertions, auth, generation locks and retention protections remain mandatory. Add any required migration only in a separately reviewed implementation PR with reversible namespace/isolation design.

Stop and report when a mandatory source stratum is absent, historical data cannot be isolated, a candidate violates identity/provenance/scope, memory/disk cap fails, or holdout has been exposed before freeze. Repair on development material, then freeze a new evaluation identity; never silently retune the consumed holdout. No source-collection cleanup, large model pull, cloud budget, fine-tuning, neural router/reranker or financial advisory agent is implied.
