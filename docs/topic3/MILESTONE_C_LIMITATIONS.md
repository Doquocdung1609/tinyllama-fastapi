# Milestone C limitations

- Scope is a local research pilot: 822 selected chunks from 2,772 available B chunks, comprising all 566 Apple chunks and 128 uniformly selected ordinal positions from each Tesla original/amendment. No claim of full Tesla coverage, all issuers or production readiness.
- All three source filings retain PARTIAL_EXTRACTION. B's four reviewed Apple tables are administrative/layout, but financial completeness remains NOT_ASSESSED; indexing does not change this conclusion.
- Fourteen development queries have source-row targets, overlapping facts and incomplete judgments of other semantically relevant passages. They are not independently held out, statistically powered, or a financial-answer benchmark. Relevance and provenance must be interpreted separately.
- Dense embeddings use the first 6,000 characters and explicit Ollama truncation. Original text is preserved; long-tail semantic coverage is not guaranteed. Installed nomic model identity and 768 dimensions are checked; no automatic download occurs.
- Custom SQLite postings avoid query-time corpus tokenization, but filtered statistics use SQL aggregates. QdrantLocal uses exact local search and membership counts. Large-scale ANN/dense performance beyond 822 chunks is NOT_MEASURED. No production scaling guarantee follows from the 5,000-chunk synthetic lexical experiment.
- Each new generation reuses unchanged postings/embeddings, then computes full selected membership/frequencies and writes a separate full dense collection. Publication is not O(delta); retained generations consume disk and have no automatic garbage collection.
- The live amendment update experiment uses a globally prepopulated embedding/posting cache; its elapsed time is not a cold incremental embedding benchmark. New-derived-revision cache invalidation is tested with fixtures.
- Provenance validation reparses frozen source files for returned filings on every request. It adds substantial end-to-end cost; retrieval-only latency excludes it explicitly. No unsafe long-lived source cache is introduced for a favorable benchmark.
- One process must own each local Qdrant directory. Close CLI clients before serving that directory; API workers must remain one for local Qdrant. A server-mode concurrency/migration architecture is outside this delivery.
- The owner's historical `knowledgebase` was not supplied on this machine. Compatibility smoke uses the existing isolated `independent_verification` collection (three vectors); direct comparison of the owner's unavailable collection is NOT_TESTED. No operation creates, deletes or overwrites that collection.
- Recovery uses controlled interruptions/exceptions and a new process for lexical restart; abrupt power loss or kill during a SQLite/Qdrant write is NOT_TESTED. No cross-store distributed transaction is claimed; readiness requires complete validation before an atomic SQLite active-pointer switch.
- Current parser/tokenizer/index versions are enforced. Arbitrary old parser replay/migration is not supplied. B's general historical derived-chunk API limitation remains; C's retained indexed generations are queryable and rollbackable.
- SEC source files, local databases, model files and private configuration remain outside Git. Reproduction requires the preserved B artifacts or independently fetched byte-identical sources with configured SEC contact User-Agent/rate limits. No new SEC requests were needed for C.
- Existing general Chat financial confusion remains a documented prompt/model limitation. Financial search supplies traceable evidence and does not certify a financial advisory answer. No unsupported accuracy claim follows from corrected individual answers.
- Memory figures exclude external Ollama RAM/VRAM and are shared process lifetime peaks unless stated. Per-mode isolated RAM and production concurrent throughput are NOT_MEASURED.
- Execution was verified on Windows/Python 3.12.10. Python 3.13 and other operating systems are NOT_TESTED; standard SQLite/JSON portability is a design rationale, not cross-platform test evidence.
