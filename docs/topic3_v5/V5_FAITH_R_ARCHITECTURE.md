# FAITH-R bounded architecture

M0: SHA-256 of each immutable saved candidate text and original chunk ID; source accession lives in the chunk ID. M1: `app/research_retrieval/faith_r.py` parses explicit issuer/year/metric, otherwise records unresolved fields. Corrected fiscal payload is an overlay in saved P7L, not a source rewrite. M2: candidates carry phrase relation, provisional table-row indication and excerpt; period, value and unit remain unknown. M3: historical six-method retrieval is retained as recorded runs. No new candidate retrieval runs because vectors/snapshots are missing. M4: stable deterministic rerank of the *same* 10 `bm25_dense` IDs; issuer, corrected period, exact row phrase, exact phrase, related phrase, year-in-body, prior rank. M5: all candidates `UNVERIFIED`; existing V4 reviewed-cell answer contract remains the only path to numerical verification.

The new feature is opt-in/read-only Research Lab data via `/research-lab/faith-r`, labelled `RECORDED_EXPERIMENT / UNREVIEWED`. It neither changes the production search route nor user indexes. A future live arm must be separately versioned and must measure retrieval and verification independently.
