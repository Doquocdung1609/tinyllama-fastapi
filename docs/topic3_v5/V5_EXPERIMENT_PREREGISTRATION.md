# V5 bounded replay preregistration — 2026-11-02

Input is the checksum-verified handoff, not a reconstructed Qdrant index. Use the recorded `B_CORRECTED` `bm25_dense` Top-10 list for each of 15 exposed development questions. Keep the same ten candidate IDs and original ordering as A1. The new M4 rule may reorder these candidates only. It cannot repair a missing candidate.

The 900-row checkpoint label counts and one AMD FY2022 example were already inspected during audit, so this is **not** a blinded preregistration. The rule is fixed before computing the rerank outcomes: (1) explicit issuer and corrected filing-period match when the query specifies them; (2) a table-like row containing the exact queried metric phrase; (3) an exact metric phrase in body text; (4) a related financial phrase; (5) target year present in body; (6) original rank. Exact phrase and related phrase are distinct; capex purchases are not automatically equal to total expenditures. Header text generated by old fiscal metadata is excluded from body matching. No learned weights, label-based tuning or hidden expansion. `UNJUDGED` remains unknown.

Evaluate after ranking against the 2026-11-01 F10 development checkpoint. Show known-positive Hit@1/3/10 and top-1 label counts, plus lower/upper bounds where unjudged items could be relevant. Do not call these independent Recall or financial-cell correctness. All 15 questions and some labels were already exposed; rerank outcomes are exploratory even if they improve.

A0/A1 are recorded historical index runs, not executed anew. A2 parses explicit query slots, A3 constructs provisional row evidence from each *same* Top-10 chunk, A4 reorders, and A5 returns `UNVERIFIED` unless a separate exact source cell has already passed review. A2/A3/A5 do not claim an extra retrieval gain. The separate six-method P5/P7L records are replayed as saved runs, not live model inference.
