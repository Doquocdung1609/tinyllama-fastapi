# Additive source-bound table index

Existing87 PDF chunks, raw source bytes, Nomic768 vectors, prefix/digest/COSINE and baseline FTS remain intact. Experiments run on `studio_workspace/search-v2-20261028`, copied while stopped; owner workspace byte inventory is checked separately. The app uses a new empty smoke workspace for Prebuilt verification. SEC generations/source registry are not rebuilt or activated.

`FinancialSearchV2` writes immutable SHA-addressed SQLite sidecars in a separately configured root (`STUDIO_SEARCH_V2_ROOT`, default ignored runtime directory). Generations bind schema/ontology versions, actual checkpoint hashes, chunk text hashes and issuer/period/type metadata. New documents or changed source layouts create another file; earlier files remain. Roll back by choosing Baseline or sending search_profile=baseline; legacy API default is baseline. React labels the new profile as a candidate, not a locked system.

Each row record links existing parent chunk,1-based PDF page, source row ID/item code, original cell strings/confidence/real boxes and source header context. It does not invent a column header, a missing number or a new embedding. Parent is selected by intersection with stored source line boxes. A separate row evidence ID prevents React key collisions when several rows share one parent. Chunk records and row records have distinct kinds.

Fielded FTS5 uses folded label/body/context with weights4/1/.2. Controlled synonyms supplement phrase matches; dates/company/question boilerplate are not blindly treated as equally useful terms. C2 searches metric-labelled rows; C3 reranks union candidates by metric/scope/period/source-statement/provenance; C4 removes incompatible financial rows and handles clarification. Baseline lexical/dense pools40 and RRF k60 remain unchanged. C3/C4 use up to40 lexical rows,40 table rows and20 baseline results; pool differences are part of the intervention, not proof of a superior RRF formula.

At query time raw files/checkpoints/chunks are hash-checked; cached sidecar bytes are checked too. New loads rederive and compare complete FTS contents to current source records. Source review facts are revalidated, not cached as permanently valid. An eligible cell must match metric, date/year, scope, basis and source unit; ambiguous periods/bases produce related evidence/clarification. Numeric arithmetic remains the existing Decimal service. SQLite handles close before atomic rename (tested on Windows).

Limitations: source-title statement classification and unit candidates are retained rather than a complete image/table semantic model; OCR-fragmented labels are not automatically repaired. Candidate geometry is not a certified financial table. Conservative scope inference can miss valid evidence. Row pool cap40 can limit large multi-document collections. No model-based reranker installed; no extra heavy model downloaded. These are documented limitations, not invented verification.

Original run bytes (including superseded diagnostics and first test) are retained in MEASURED_RUN_SNAPSHOTS.zip; per-entry hashes are in its manifest. Final result JSON files use one record per line without changing any measured values.
