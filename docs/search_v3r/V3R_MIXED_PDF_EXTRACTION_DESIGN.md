# V3R region extraction design

Create an opt-in owned derived workspace,with a versioned policy marker and immutable per-document manifests. Existing PdfWorkspace behavior/legacy extraction,raw PDFs,accepted Nomic768 vector configuration and all old index generations remain available. Reuse only hash-verified prior checkpoint tokens when geometric/content evidence says a region is already represented;carry their ancestry into the new generation. Reused OCR is still unverified OCR,not reviewed financial truth.

For each page,preserve native word boxes in the rotated PDF viewport. Identify actual embedded-image rectangles,clip/merge overlapping regions and render bounded crops. Inspect raster ink/components/row distribution/grid structure and the ink represented by native/prior token boxes. Character count and image-area fraction are diagnostics,never the sole decision. Text-like image regions with substantial unrepresented ink receive regional Tesseract OCR. Decorative/sparse regions are separately labelled;uncertain regions produce coverage warnings. OCR failure or empty output in a structurally plausible table must remain visible.

Keep OCR raw strings,language,DPI,confidence,source-image/crop hash,source rectangles and rotation transforms. Convert reading coordinates consistently across native/OCR layers. Fuse duplicates by source geometry and token identity;preserve conflicting readings as alternatives/warnings rather than silently correcting digits. Native text is retained. Work one region/page at a time with bounded pixels/time;no paid OCR or new model.

Build row candidates within region/table segments,not a shared anchor pool for unrelated tables. Preserve labels,row codes,raw cell strings,blank slots,source boxes and confidence. Header/period/unit candidates must contain actual source strings/rectangles;unresolved group/currency/column mapping remains unverified. Document SHA,page,region/table IDs,provenance and verification state accompany each candidate. Never automatically mark OCR REVIEWED or generate financial answers from it.

Completion is layered:PROCESSING_COMPLETE,EXTRACTION_COMPLETE under the stated region policy,EXTRACTION_COVERAGE_WARNING,FINANCIAL_EVIDENCE_REVIEW_PENDING. FINANCIAL_EVIDENCE_REVIEWED belongs to an audited specific cell only. A document with one reviewed cell is not a fully reviewed financial statement. Add fields without replacing legacy READY/API contracts;React displays remaining-region warnings and review-pending states.

Gate technical extraction before search changes:recover all seven SEM source values in the correct labelled row/current-KRW column,with actual year/currency header candidates and source coordinates checked against images. Cross-document sampled pages and decorative/duplicate/rotated cases are measured separately. Raw strings appearing anywhere are insufficient evidence of correct-cell recovery. If Gate B/D fails,record the failure before considering retrieval claims.

After that gate,compare old extraction+V3,new extraction+unchanged V3,and a separately versioned region-context index using the same sources/gold queries. V3's84 questions are regression only. Freeze code/config/index policy before collecting new unseen sources/questions. Agent-only labels remain PROVISIONAL_AGENT_ANNOTATED and acceptance stays PARTIAL pending owner audit. Profiling will distinguish index preparation,embedding,FTS,Qdrant,row/reranking,verification and browser work;prewarm may move index work off the first query but must not skip source verification.


## Final implemented contracts

Opt-in DerivedPdfWorkspace refuses in-place upgrade of an old workspace and binds the extractor source hash, locked model digest, raw SHA, page checkpoint hashes, ancestry and chunk membership to immutable manifests. Source-record and region-context FTS generations remain separate files. A rehashed replacement checkpoint is rejected if its membership differs from its sealed generation. Every query still hashes the actual checkpoint payloads and PDFs; cached metrics do not replace source verification.

The region layout view is `TABLE_LAYOUT_V3R_REGIONS_V2_FRAGMENTS`. New fragment rows retain source coordinates and remain unreviewed. The eight inherited reviewed cells were carried only after exact raw PDF, displayed string, cell box and current header/scope/unit validation; immutable events retain parent audit hashes. Document-level review stays pending. Changing the layout required a fresh audited continuity event, not silently accepting an old evidence hash.

V3R is an additive `production_v3r` profile on derived roots. Legacy root selection and baseline/V2/V3 profiles remain supported. The baseline comparison arms remain BM25/Dense/Hybrid; the selected product candidate is additional. SEC uses the prior V3 source-only adapter and existing generations. No SEC ingestion or migration is performed here.

Workspace-owned background preparation starts at derived-root startup and after upload/retry completion or deletion. Changes during preparation coalesce into another refresh. A request while preparing receives explicit SEARCH_INDEX_PREPARING; React displays preparation state. Failed preparation stays visible. No dummy financial query is used. Embedding-model cold loading can therefore remain visible on the first real dense request.
