# V3R owner-laptop performance

These are measured observations on Windows, Python 3.12 and NVIDIA GeForce RTX 3050 Laptop GPU (4096 MiB), not projections. The snapshot reports 15.23 GiB physical RAM. Local Qdrant runs inside the Python process. CPU Tesseract performs regional OCR; the locked Nomic model supplies 768-dimensional embeddings through existing Ollama. No larger model, paid OCR or GPU OCR was added.

The first no-prewarm query over the seven-document / 309-page derived corpus took **71.13 seconds**. It includes initial sidecar preparation. This is larger than the older five-source cold observation and is not claimed as faster. The operational repair moves construction to explicit startup/post-READY preparation. Final Prebuilt background preparation took **58.31 seconds**, reported as PREPARING while underway; user queries do not silently trigger that work.

Dedicated final repeated-query profiling: warm p50 **1363.7 ms**, p95 **1529.0 ms** over ten calls. Actual final HTTP smoke after startup measured 5125.81 ms for the first request, then 1312.13 and 1620.43 ms. Nomic cold loading/resource contention can still affect the first dense request. No promise of a sub-two-second cold SLA is made. The harness has no dummy financial warm-up query.

PERFORMANCE_RAW.json preserves the pre-optimization measurement: warm p95 4212.31 ms. Profiling found duplicate deserialization of every OCR JSON payload in manifest verification. The optimized verifier checks the sealed page/chunk hash membership without reparsing payloads; FinancialSearchV2.prepare still hashes every actual payload, chunk and PDF and verifies sidecar bytes. A rehashed out-of-generation checkpoint regression still fails closed. Cached metric annotations are keyed by verified source generation.

PERFORMANCE_OPTIMIZED_RAW.json contains per-call workspace BM25, query embedding and Qdrant times plus raw cProfile functions for source verification, row lookup and reranking. One initial nested call measured BM25 46.60 ms, embedding 30.70 ms, Qdrant 29.16 ms. Cumulative profiler entries overlap and must not be summed. The final development ablation timings came from an earlier loaded verifier under concurrent tests; the dedicated optimized run is the final performance reference.

Sampled Python peak RSS: **811.5 MiB**, including local Qdrant, excluding external Ollama and Chrome. Free disk at profiling: **75.45 GiB**. Actual process RSS/model offload/GPU usage are separately recorded in OWNER_MACHINE_RESOURCE_SNAPSHOT.json. Whole-machine VRAM was NVIDIA GeForce RTX 3050 Laptop GPU, 4096 MiB, 3619 MiB; that includes unrelated applications and must not be attributed entirely to V3R.

**Observed memory-pressure warning:** minimum system available RAM during the optimized concurrent measurement was 12.6 MiB; the later machine snapshot had only 73.9 MiB available. Other owner applications were present and were not stopped. This is not an isolated capacity or memory-leak test. The bounded smoke passes do not prove stability under continued machine-wide memory exhaustion. Before a presentation, allow preparation to finish and check available RAM; no unrelated owner process was killed to obtain better numbers.

Development region audit: 33.35 seconds, parent RSS 258.5 MiB, combined sampled OCR/parent peak 381.0 MiB, parent CPU 14.77 seconds, sampled child CPU lower bound 17.91 seconds. The 309-page derived ingestion reused authenticated prior OCR and took 300.05 seconds; it is not fresh OCR speed. Fresh PNJ 28-page ingestion took 206.92 seconds; per-page regional analysis/OCR/fusion totals 188.35 seconds. Fresh mostly-native ACB 78-page ingestion took 41.26 seconds; the corresponding regional total is 17.26 seconds. Indexing/embedding time is included in ingest totals, not in per-page extraction times.

Actual Chrome source/search rendering scenarios complete in the recorded 20.6-second three-test run. Individual full-test times include navigation, API calls and assertions and are not isolated React render timings. Six representative screenshots were visually inspected against the existing navy-sidebar/blue-action/card UI references; the viewer/source panel, comparison columns and warning states retain that layout. No pixel-identical design claim or fabricated frontend-only render p95 is made.

The isolated tessdata_best English trial was not adopted. The original eng/vie/osd hashes and locked Nomic digest remain unchanged. No resource warning or failed experiment is hidden.
