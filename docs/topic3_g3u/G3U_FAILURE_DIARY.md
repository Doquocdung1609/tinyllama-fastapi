# G3U failure diary and corrections

1. **G3T AI exact risk:** `12_02` and `15_01` were labelled exact by applying the prospective minimum-answer rule while their C1 comparative scope remained pending. The G3U overlay holds both from a strict exact subset without changing the frozen C1/C2 ledgers. In a systematic sample of eight earlier numeric questions (19 cells), only six cells had an explicit scale phrase in the same table; thirteen require surrounding-heading or human unit confirmation. This is an observed limitation, not a claim that the filings lack units.
2. **AMD static-search ambiguity:** the first local diagnosis used `CORPUS_PRESENT_WRONG_SCOPE` because the phrase “Data Center” occurs in risk prose. Inspection of all 68 and 69 original chunks showed only Part II risk/exhibit sections and no target numeric value. A new immutable V2 diagnosis classifies the missing financial table as `SOURCE_PRESENT_CORPUS_CHUNK_MISSING`; V1 was preserved.
3. **Test fixture error:** the first G3U test edit accidentally placed two human-review assertions in the wrong test function, causing one `NameError`. The fixture was corrected and the targeted suite rerun successfully. No production logic or frozen artifact was changed to hide it.
4. **Research dependency conflict repaired:** installing `fastembed==0.7.4` for a bounded non-G2 model smoke downgraded Pillow below the existing `pdfplumber` requirement. The partial G2 run used that research version. After abort, the environment was upgraded to `fastembed==0.9.1` and Pillow `12.3.0`; `pip check` now reports no broken requirements. The owner-approved v2 run discloses the updated runtime. This is an environment issue, not a benchmark observation.
5. **RRF protocol discrepancy found after the pool started:** the YAML/v1 protocol claim 60, while the native executable Qdrant fusion default is 2. The run was stopped immediately on confirmation. The private partial log has 16,020 lines, 801 question/arm/index executions, SHA-256 `87b6058236045d84be79d0773582e849920114d1657143071ec294a82fcd5bc0`. No per-hit rank or score was inspected and no blind/qrel/metric output was produced from that partial run. The runner was repaired to fail closed for v1. The owner subsequently approved one v2/native-default-2 complete pool run with this partial exposure disclosed; it produced 31,760 hit rows and 5,792 blind pairs. The aborted file remains `POOL_PARTIAL_ABORTED_PROTOCOL_CONFLICT`, not `POOL_GENERATED`.
6. **Zero-result run provenance:** the v2 runner asserted 1,692 executions but emitted only hit rows. The independent audit found 104 arm/question combinations without hit rows; the sealed log alone cannot distinguish genuine zero results from omitted calls. This is recorded as a pool provenance limitation. The one approved run was not repeated to make the record appear cleaner.

No G2 held-out quality score, final benchmark, FAITH-R tuning or human approval was produced while investigating these issues.
